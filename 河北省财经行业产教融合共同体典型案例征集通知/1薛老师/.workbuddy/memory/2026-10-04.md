# 2026-10-04 工作日志

## IMA 税务知识库：资料库建成前体检

目标：评估 `1薛老师` 文件夹（税务资料，计划做 IMA 知识库）是否适合按当前模式继续整理。

### 勘察结论（全部实测，非推测）

规模：71 个文件，40.1 MB，最大深度 2 层。

**格式实测**（olefile 校验 magic bytes + node preflight-check.cjs 全量预检）
- 49 个 OLE2 老格式（47 .doc / 1 .ppt / 1 .xls），22 个 OOXML
- 全部由 WPS 生成（流内含 `KSOProductBuildVer`）
- 预检结果：70 个 pass，1 个 fail
- **唯一硬阻塞**：`2023年个人所得税汇算清缴公告.ofd` —— IMA 不支持该扩展名
- IMA 官方支持 .doc（查 ima.qq.com 官方文档确认），所以老格式本身可上传

**最关键的发现：图片型文档**
用 olefile 统计每个文件的 `Data` 流（WPS 图片存储池）占比后发现：
| 文件 | 体积 | 图片占比 |
|---|---|---|
| 纳税人操作手册(1)(1).doc | 27.49 MB | 97.7%（30+ 张图） |
| 2027-12-31结束的税收政策.doc | 3.73 MB | 93.6%（30 张图） |
| 备注栏.doc | 0.53 MB | 95.1% |
| 转让不动产的预缴税额.doc | 0.10 MB | 86.9% |
| 土地增值税税率.doc | 0.03 MB | 61.3% |
| 开发商销售房产需要交纳什么税.doc | 0.06 MB | 54.4% |

**3 个最大的文件占了全部体积的 79.2%，但正文极小** —— 典型的"体积大、机器读不到"。
风险：IMA 对嵌入 .doc 内部的图片大概率不做 OCR，这些文件会变成检索盲区。

**结构问题**（三套分类维度混用）
- 主题维度：农村集体制度 / 出口企业 / 发票相关 / 房产土地相关 / 残疾人政策 / 税局风险任务
- 来源维度：税协培训 → 2014.3.7个税培训文件夹
- 类型维度：财务专业用表
- 根目录 3 个孤儿文件未归类
- 交叉重叠：农村集体制度 ↔ 房产土地相关（农村房产出租、村集体拆迁款）

**命名问题**（脚本扫描）
- 23 个以数字序号开头 → IMA 按字符串排序会变成 1,10,11,...,2,20,21
- 特殊符号：`→`（2 个）、`――` 全角破折号（1 个）、`(1)(1)` 重复下载标记
- 缺主语：`备注栏.doc`
- 疑似错别字：`土地补充的税`（应为"补偿"）、`那些与税收有关`（应为"哪些"）
- 日期歧义：`2027-12-31结束的税收政策`

**领域特有的致命问题：时效性缺失**
税务政策强时效性，IMA 检索不区分新旧，71 个文件里仅 2 个标注了年份/文号。
建议文件名加时效前缀（现行/已废止/YYYY年底到期）。

### 给出的建议
1. 删换 .ofd；6 个图片型文档需 OCR 或补文字版
2. 统一为单一分类维度（按税种/业务）
3. 命名模板：`时效_主题_文号_年份.ext`
4. Excel 计算模板（含公式）不入库，另存为工具
5. 先小批量试传 5 个验证 IMA 解析效果，再全面铺开

### 复用的判定方法
- `olefile.OleFileIO(path).listdir(streams=True)` → 看 `Data` 流占比判断图片型文档
- `node <skill>/scripts/preflight-check.cjs --file <p>` → 权威判断 IMA 是否支持
  - 注意：Git Bash 传中文路径给 node 会因编码失败，必须走 PowerShell 调用
  - PowerShell 调用 node 时中文文件名会乱码，但 `pass` 字段本身可信
